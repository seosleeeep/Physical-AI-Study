# Rosbag을 이용한 차량 주행 기록 및 재현

## 1. 개념

Rosbag
: ROS 2 토픽 메시지를 시간 순서대로 저장하고 다시 발행하는 도구

## 2. 구현 과정

### 2.1 기록용 QoS 설정

처음 기록할 때 `/tf`의 Durability 설정이 맞지 않아 일부 좌표 변환이 기록되지 않는 경고가 발생함,,
-> 다음 설정을 `~/jazzy_car_ws/bags/record_qos.yaml`에 작성하여 해결했다.
(Rosbag의 /tf 구독이 transient_local로 설정된 상태에서 volatile 발행자가 발견되어 Durability QoS 불일치가 발생했다. 기록용 설정 파일에서 /tf의 Durability를 volatile로 명시하여 이후 발행되는 좌표 변환을 수신·기록하도록 해결했다.)

```yaml
/tf:
  history: keep_last
  depth: 100
  reliability: best_effort
  durability: volatile

/tf_static:
  history: keep_last
  depth: 100
  reliability: reliable
  durability: transient_local

/robot_description:
  history: keep_last
  depth: 1
  reliability: reliable
  durability: transient_local
```

QoS
: 메시지 송수신 규칙. 계속 갱신되는 `/tf`는 `volatile`로 수신하고, 고정 좌표계와 차량 설명은 기록 시작 전의 데이터도 받을 수 있도록 `transient_local`로 설정함.

### 2.2 주행 기록

Gazebo와 방향키 조종창을 실행한 상태에서 별도 터미널로 기록을 시작함.

```bash
source /opt/ros/jazzy/setup.bash
source ~/jazzy_car_ws/install/setup.bash

mkdir -p ~/jazzy_car_ws/bags

ros2 bag record \
  --use-sim-time \
  --qos-profile-overrides-path ~/jazzy_car_ws/bags/record_qos.yaml \
  -o "$HOME/jazzy_car_ws/bags/car_drive_$(date +%Y%m%d_%H%M%S)" \
  --topics \
  /clock /tf /tf_static /joint_states /robot_description \
  /diff_drive_controller/cmd_vel \
  /diff_drive_controller/odom \
  /camera/image /camera/depth_image \
  /camera/camera_info /camera/points
```

| 옵션 | 의미 |
|---|---|
| `--use-sim-time` | Gazebo 시간을 기준으로 기록 |
| `--qos-profile-overrides-path` | 기록용 통신 설정 적용 |
| `-o` | 날짜·시간별 저장 폴더 지정 |
| `--topics` | 기록할 토픽 선택 |

기록이 시작된 것을 확인하고 방향키로 임의의 경로를 주행함. (주행 후 차량을 정지하고 기록 터미널에서 Ctrl+C를 눌러 저장을 종료.)

### 2.4 재생 설정

Gazebo와 조종창을 종료하고, 재생용 설정을 `~/jazzy_car_ws/bags/play_qos.yaml`에 작성했다.

```yaml
/tf:
  history: keep_last
  depth: 100
  reliability: reliable
  durability: volatile

/tf_static:
  history: keep_last
  depth: 100
  reliability: reliable
  durability: transient_local

/robot_description:
  history: keep_last
  depth: 1
  reliability: reliable
  durability: transient_local
```

RViz를 시뮬레이션 시간으로 실행했다.

```bash
source /opt/ros/jazzy/setup.bash
source ~/jazzy_car_ws/install/setup.bash

rviz2 \
  -d ~/jazzy_car_ws/install/simple_car/share/simple_car/rviz/rgbd.rviz \
  --ros-args -p use_sim_time:=true
```

차량 이동을 고정된 기준에서 관찰하도록 다음을 설정했다.

- **Global Options → Fixed Frame:** `odom`
- **Views → Current View → Target Frame:** `odom`

### 2.5 기록 재생

새 터미널에서 실행했다.

```bash
source /opt/ros/jazzy/setup.bash
source ~/jazzy_car_ws/install/setup.bash

ros2 bag play \
  ~/jazzy_car_ws/bags/car_drive_20261001_030028 \
  --qos-profile-overrides-path ~/jazzy_car_ws/bags/play_qos.yaml \
  --delay 5
```

`--delay 5`는 5초 기다린 뒤 재생하는 옵션이다. 기록에 `/clock`이 포함되어 있으므로 별도의 `--clock` 옵션은 사용하지 않았다.

## 3. 검증 결과

- 방향키로 직접 조종한 차량의 주행을 기록했다.
- `ros2 bag info`로 주행·좌표계·센서 메시지가 저장되었음을 확인했다.
- Gazebo를 종료한 상태에서 Rosbag을 재생하여 RViz에서 기록된 차량 움직임을 확인했다.
- 직접 주행한 영상과 저장된 주행을 재생한 영상을 각각 확보했다.

이를 통해 **차량 주행 데이터를 저장하고, 저장한 데이터를 이용해 움직임을 재현하는 과제**를 완료했다.

## 4. 질문 및 문제 해결 피드백

| 실습 중 질문·상황 | 원인 및 해결 | 배운 점 |
|---|---|---|
| 처음 배치로 되돌리고 싶음 | 기록을 종료하고 Gazebo Launch를 다시 실행하여 초기 배치로 복귀 | 시뮬레이션을 재시작해도 저장된 Bag은 유지됨 |
| 조종했지만 기록 프로그램이 꺼져 있었음 | 기록 시작을 확인한 뒤 다시 주행 | 차량 실행과 데이터 기록은 별도 작업임 |
| `/tf` QoS 경고 발생 | 기록용 YAML로 QoS를 명시하고 새로 기록 | 토픽이 있어도 QoS가 맞지 않으면 메시지가 기록되지 않을 수 있음 |
| RViz만 실행했는데 차량이 보이지 않음 | Rosbag 재생을 시작하자 차량이 표시됨 | RViz는 데이터를 표시하는 도구이므로 데이터 발행이 필요함 |
| 차량이 정지한 것처럼 보임 | 화면이 차량을 따라갈 수 있어 Fixed Frame과 Target Frame을 `odom`으로 확인 | 좌표 기준과 시점의 추적 대상은 구분해야 함 |
| 재생 중인 것을 놓침 | 기록을 처음부터 다시 재생 | 정지 구간도 기록되고, 재생은 약 89초 뒤 종료됨 |
| 화면 녹화를 위해 다시 보고 싶음 | `ros2 bag play`를 다시 실행 | 재주행·재기록 없이 반복 재생 가능 |
| 특정 시점부터 재생하고 싶음 | `--start-offset 20`으로 기록 시작 20초 뒤부터 재생 가능 | 시작 위치를 지정할 수 있음 |
| 재생을 잠시 멈추고 싶음 | 재생 터미널에서 Space로 일시정지·재개 | 재생 중 화면 확인 시간을 확보할 수 있음 |
| GitHub 영상 업로드가 안 됨 | 업로드 방식별 용량·형식 제한을 확인했고 이후 업로드 성공 | 영상 길이 외에도 파일 크기와 업로드 방식을 확인해야 함 |

이번 실습에서는 '실행 → 기록 → 저장 확인 → 재생 → 화면 검증'을 각각 확인하는 것이 중요했다. 특히 기록 프로그램의 실행 여부와 RViz 좌표계 설정을 먼저 확인하면 문제 원인을 빠르게 찾을 수 있다.
